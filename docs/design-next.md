## C. どんな牌の組み合わせでも全牌がドラになりうること

**調査結果: 現行ロジックで既に満たしています。**

- `Tiles.nextDora(kind, avail)` は山に無い牌種を飛ばして順送りする（`js/tiles.js:191`）。
  表示牌は必ず山にある牌なので、各系列（萬/筒/索/風/三元）内で「山にある牌種の巡回」になり、全牌種がドラになりうる。
- 牌種グループ 7 つの全組み合わせ 127 通りを総当たりで検証し、ドラにならない牌種は **0件**。
  - 例: 萬子19のみ → 1m表示→9m、9m表示→1m ／ 筒子28のみ → 8p表示→2p（ご提示の例と一致）
- 実装作業: 上記の総当たり検証を `tests/test.js` に追加して、今後の変更で壊れないようにする。
- → **もし実際に「ドラにならない牌」を見かけたなら、その時の設定（山に入れる牌・赤ドラ等）を教えてください**（別のバグの可能性）。

## E. 条件付き自動ツモ切り（欲しい牌が来るまで他を切る）

### 挙動（回答反映済み）

- トリガーは卓左上の「自動ツモ切り」トグルのまま。
- 設定で「欲しい牌の条件（ルール）」を指定。ツモのたびに次の通り自動打牌する:
  1. **ツモ牌が欲しくない牌** → ツモ切り
  2. **ツモ牌が欲しい牌** → ツモ牌を手に残し、手牌の「欲しくない牌」から**ランダムに1枚手出し**
  3. 手牌がすべて欲しい牌（切れる欲しくない牌が無い） → 停止して手動操作を待つ
- **目標達成で停止**（下記の枚数・AND/OR 判定）。停止時はトーストで通知。
- ルールが1つも無い場合は現行どおり「常にツモ切り」。
- 優先順位は現行を維持: 自動和了 → 自動カン → 目標判定 → 自動打牌。
  和了形・カン可能時は自動打牌しない（現行どおり）。
- リーチ中は手出しできないため、欲しい牌でもツモ切り（リーチ後自動ツモ切りと同じ扱い）。
- 手出しした牌は河で「手出し」表示（ツモ切りの暗め表示にしない）。

### 条件ルール（複数設定可）

1ルール = 以下の属性の組み合わせ（**ルール内は AND、各属性の中の選択肢は OR**）＋枚数＋数え方。

| 属性 | 選択肢 |
| --- | --- |
| 種類 | 萬子 / 筒子 / 索子 / 風牌 / 三元牌 |
| 数字 | 么九（1・9）/ 中張（2〜8）/ 個別の数字 1〜9（数牌のみ） |
| ドラ | 表ドラ / 赤ドラ（カンドラ含む） |
| 役牌 | 場風・自風・三元牌（設定の場風・自風に連動） |
| 特定の牌 | 牌種を直接指定（例: 5p, 中） |
| 枚数 N | 既定 1 |
| 数え方 | **ツモ累計**（開始後に条件に合う牌を N 枚ツモった）／ **手牌の保持数**（手牌＋カンに条件に合う牌が N 枚ある） |

- 例: 「索子 かつ 中張」保持6枚 AND 「ドラ」保持2枚
- **ルール間の結合は AND / OR を設定で選択**（OR: どれか1つ達成で停止、AND: 全ルール達成で停止）。
- 「欲しい牌」= いずれかのルールの条件に合う牌（結合方式によらず、手出し対象から除外する牌の判定は OR）。
- ツモ累計のカウントはトグルを ON にした時点／配牌リセット時に 0 へ戻す。
- 判定は純関数としてロジック側に追加し（`AutoDiscard.matches(tile, rule, ctx)`、`AutoDiscard.goalReached(...)`、
  `AutoDiscard.pickDiscard(...)`）、`tests/test.js` でテストする。
- 設定の保存形式（localStorage）:
  ```js
  autoDiscard: {
    combine: 'or',            // 'or' | 'and'
    rules: [
      { suits: ['s'], nums: ['simple'], dora: [], yakuhai: false, kinds: [],
        count: 6, countMode: 'hold', enabled: true },  // countMode: 'draw' | 'hold'
    ],
  }
  ```
- UI: 設定の「自動」タブにルール一覧（行ごとに チップ選択＋枚数＋数え方＋有効/削除）、結合方式、「＋ルール追加」。
  卓左上のトグルに、ルールが有効な場合は進捗（例: `索中張 4/6`）を小さく表示。

## F. 設定ダイアログのタブ化（ご質問への回答）

**タブ化を推奨します。**

- 理由: 現在でも約20項目あり、E のルール編集 UI が加わると縦に長くなりすぎる。特にスマホ横向きは縦が狭く、スクロール量が大きい。
- タブ案:
  1. **表示**（牌の表示・操作キー表示）
  2. **操作**（自動ツモ・打牌の操作・ツモ簡略化・リーチ後自動ツモ切り）
  3. **自動**（条件付き自動ツモ切りのルール ／ 配牌の自動リセット）
  4. **局・山**（場風・自風・赤ドラ・山に入れる牌・ツモ回数上限・他家模擬）
- 実装: 既存の `<h3>` 区切りを `<section data-tab>` に分け、上部にタブボタン。最後に開いたタブを localStorage に記憶。
  JS の設定バインド（`set-*` の ID）はそのまま使えるので改修は HTML/CSS 中心。
- スマホ横向きではタブを左側の縦並びにして縦幅を節約。

## 決定事項

- 手出し: 欲しくない牌から手出し。候補が複数なら**牌効率で最も不要な牌**（同点内はランダム）
- 枚数の数え方: ツモ累計／保持数を選択式
- ルール結合: AND / OR を選択式
- 目標達成で停止後: **トグルは ON のまま**（手動で打牌後は通常の自動ツモ切りに戻らず停止状態を維持。トグルを入れ直すとカウントリセットして再開）
- 牌画像: 外部素材を先に探す。画像表示を**既定**にする
- アイコン: **中**
- ドラ: 現行で問題なし（テスト追加のみ）
