状態: **実装済み**（末尾「決定事項」の通り）

## 現状の挙動（確認結果）

| 動作 | 現状 |
| --- | --- |
| 打牌 | ツモ牌が欲しくない牌ならツモ切り。欲しい牌なら、手牌の**欲しくない牌**から牌効率で最も不要な1枚を手出し |
| 「欲しい牌」の判定 | いずれかの項目に合えば欲しい牌。**目標枚数に達していても欲しい牌のまま**（切る候補にならない） |
| 目標達成 | `ad.stopped = true`、「目標達成」トースト |
| 切れる牌が無い | `ad.stopped = true`、「切れる牌がありません」トースト |
| 停止の解除 | **Z キー／ボタンで入れ直すか、配牌リセットのときだけ**。手動で手出ししても再開しない（2 種類の停止を区別していない） |
| 枚数の上限 | 全項目 1〜14 に丸めるだけ。牌の枚数（1種4枚・赤は最大3枚など）や、組み合わせとして達成できるかは見ていない |

画像の例（AND・保持数、1萬×3・2〜8萬×1・9萬×3）では手牌 14 枚がすべて萬子（欲しい牌）になり、8萬が 3 枚目
（目標 1 枚に対して 2 枚余り）でも切れずに「切れる牌がありません」で止まっていた。

## 1. 達成できない条件の弾き方／停止からの再開

### 1-1. 「合計 > 14」では判定できない

1 枚の牌が複数の項目に同時に数えられる（例: 5萬は「萬子」「5」「中張」の 3 項目に数えられる）ので、
**目標枚数の単純な合計は判定に使えない**。

- 例: 「萬子×9 AND 中張×9」は合計 18 だが、中張の萬子 9 枚で達成できる。
- 逆に、合計が 14 以下でも達成できない条件がある: 「1萬×5」（1 種は 4 枚まで）、「赤ドラ×4」（赤は最大 3 枚）、
  山に入れない牌を指定した場合など。

### 1-2. 判定方法（提案）

山の牌を「どの項目に合うか」で分類し（牌種×赤か、最大 37 クラス）、次の問題が解けるかを調べる。

> クラス c から x_c 枚（0 ≤ x_c ≤ 山にある枚数）選ぶ。Σx_c ≤ 14 で、
> どの項目 i についても「i に合うクラスの x_c の合計」≥ 目標枚数 i

- 14 枚以内の小さな整数計画なので、「まだ足りない項目を 1 つ選び、それに合うクラスから 1 枚足す」深さ優先探索で十分
  （下限 = 足りない枚数の最大値 で枝刈り。念のため探索回数に上限を設け、超えたら「判定できません」扱い）。
- 各項目の入力欄の上限もこの考えで決める: `kind:*` は 4、赤ドラは山の赤の枚数、三元牌は 12、どれも最大 14。
- **ドラは局ごとに変わる**ので、設定画面ではドラ項目を「他の項目と重ならない 4 枚」とみなして判定し、
  実際のドラが決まる配牌時・カン時に改めて正確に判定する。
- 数え方が**ツモ累計**の場合、14 枚の制限は無い（山にある枚数だけが上限）。

### 1-3. 弾き方（提案）

| タイミング | 動作 |
| --- | --- |
| 設定画面 | 条件を変えるたびに判定し、達成できない場合は条件一覧の下に赤字で理由を表示（例: 「1萬は4枚までです」「14枚では揃いません（最少 16 枚）」）。**入力は拒否しない**（途中の状態を作れなくなるため） |
| 開始時（Z キー） | 達成できない条件なら開始せず、トーストで理由を表示 |
| 配牌時・カン時 | ドラを含めて判定し直し、達成できなくなったら停止して通知 |

### 1-4. 停止からの再開

停止を 2 種類に分ける。

| 種類 | 解除 |
| --- | --- |
| **目標達成** | これまでどおり ON のまま停止を続ける（入れ直すかリセットで再開）。手動で欲しい牌を切って目標を割っても再開しない |
| **切れる牌が無い** | その場限りの停止にする。手動で手出しした後、次のツモから自動で判定し直す |

ただし 2 の提案を採用すると「切れる牌が無い」停止は起きなくなる（常に何かを切る）ので、この区別は不要になる。

### 1-5. 確認用のテスト（`tests/test.js` に追加）

- 判定: 「萬子×9 AND 中張×9」→ 達成可能、「1萬×5」→ 不可、「1萬×4 AND 9萬×4 AND 5萬×4 AND 東×3」→ 不可（15 枚必要）
- 保持数・AND: 目標達成で止まる → 手動で1枚切る → 次のツモでは止まったまま
- （2 を採用しない場合）切れる牌が無くて止まる → 手動で手出し → 次のツモで再開 → 目標達成で止まる

## 2. 目標を超えて持っている牌を切れるようにする

### 提案: 「欲しい/欲しくない」の 2 値をやめ、「足りない枚数（不足）」を最も増やさない牌を切る

不足 = Σ_項目 max(0, 目標枚数 − 手牌＋カンの枚数)

手牌 14 枚それぞれについて「これを切ったら不足がいくつ増えるか」を計算し、次の優先順で切る牌を選ぶ。

1. 不足が増えない牌を優先
   - どの項目にも合わない牌（これまでの「欲しくない牌」）
   - 目標を超えている牌（画像の例では 3 枚目の 8萬、2 枚目の 2萬・7萬など）
2. その中では「まだ目標に届いていない項目」に合う数が少ない牌を優先
   （届いていない項目に役立つ牌を残すため）
3. 最後に牌効率（3 の方式）

- これで画像の例は 8萬などを切って続行し、1萬を 3 枚引いた時点で止まる。
- どの牌を切っても不足が増える場合も、増え方が最も小さい牌を切って続行する。これにより
  「萬子×10 AND 中張×10」で手牌が 1萬・9萬・筒子の中張だけになって詰まる、のような状態からも少しずつ抜け出せる。
  → **「切れる牌が無い」停止は起きなくなる**（止まるのは目標達成・和了・カン・山切れ・ツモ回数上限のときだけ）。
  条件が達成できない場合に延々と続かないよう、1 の開始時チェックとセットで入れる。
- 数え方が**ツモ累計**の場合も、手牌の残し方は同じ考え方（手牌の枚数で不足を計算）で行う。
  ツモ累計の目標は手牌と関係なく進むので、手牌が詰まって止まることは無い。
- ツモ牌を手に残すかも同じ基準で判断する（ツモ牌も 14 枚の候補に入れる。ツモ牌が選ばれればツモ切り）。
  同じ評価の牌が手牌とツモ牌にあれば、ツモ牌を切る（河の手出し表示を減らすため）。
- OR・合計枚数では、目標超過は目標達成で止まった後にしか起きないので、実質的に変わるのは AND の場合。
- 実装: `pickDiscard(tiles14, cfg, ctx, analysis, held)` を上記の評価に置き換え、`isWanted` は進捗表示などに残す。

## 3. 牌効率で手牌が同じ形に固まる問題

現状は「欲しくない牌のうち受け入れが最大になる牌」を切るので、同じ手牌なら毎回同じ牌を切る（ランダムなのは同点のときだけ）。

| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| A. 現状維持（牌効率最善） | — | 手が最も早く進む | 形が固まる |
| B. 向聴を落とさない範囲でランダム | 切っても向聴数が悪くならない候補から一様ランダム | 手を壊さずに形がばらける。実装が簡単（`analysis` の shanten だけ使う） | 受け入れの差は無視する |
| C. 上位 n 種からランダム | 受け入れ順の上位 n 牌種から選ぶ | 強さを n で調整できる | n の意味が手牌によって変わる（候補が 2 種しか無いときなど） |
| D. 完全ランダム | 候補から一様ランダム | 最もばらける | 手がほぼ進まず、自然な手牌にならない |

- どの方式でも 2 の「不足」による優先は先に適用し、この方式は最後の選び方にだけ使う。
- 提案: 設定「自動」タブに **手出しの選び方: 牌効率 ／ 向聴を保ってランダム ／ 完全ランダム** を追加し、既定は牌効率（現状どおり）。
  対子落とし・ドラ保持・残り枚数などを考える「より人間らしい打牌」は範囲が広がりすぎるので見送る。

## 4. 目標枚数の入力 UI

### 問題

- 選択すると入力欄が表示されて（`display: none` → 表示）セルの高さや幅が変わり、周りがずれる。
- 文字の項目は入力欄が横に並ぶため、「三元牌」が「三…」のように切れる。
- `input type="number"` の矢印は小さく、iPhone/iPad の Safari では**矢印自体が表示されない**。

### 案

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A. 入力欄の場所を常に確保 | `visibility: hidden` で隠し、ずれを無くす | ずれは直るが、文字が切れる問題は残る。空白が増える |
| B. 特定の牌だけ横に置く | 牌の左右の余白に入力欄を移す | 広い画面では収まるが、スマホでは 9 列で 1 列 30px 程度になり入らない |
| C. 牌・ボタンに枚数バッジを表示 | 選択中の項目の右上に `×3` を表示。長押し・右クリック・ホイールで増減 | 表示は良いが、操作が分かりにくく、タッチ操作で困る |
| **D. 選択中の条件を別の一覧に分ける（推奨）** | グリッドは選択（ON/OFF）だけにし、上部に「選択中」の一覧を置く: `1萬 [−] 3 [+] ✕`。グリッドの項目には C のバッジ `×3` だけ表示 | ずれない・文字が切れない・スマホでも押しやすい。一覧から直接解除でき、並び順＝下の進捗表示の順（先頭 4 件）にできる |

- D の場合、入力は `input type="number"` をやめて `−`／`+` ボタンにする（上限は 1-2 の値）。
- 合計枚数モードでは一覧の枚数を隠し、項目名と ✕ だけにする（現状の「合計のときは入力欄を隠す」と同じ扱い）。
- 1 の「達成できない」表示は一覧の直下に出す。

## 決定事項

1. 2 の「不足を最も増やさない牌を切る」方式を採用（「切れる牌が無い」停止は廃止）。1 の判定（設定画面の警告・開始時の拒否・配牌時/カン時の再判定）もあわせて実装
2. 目標達成後に手動で目標を割っても再開しない（現状維持）
3. 手出しの選び方は 3 方式すべて追加（牌効率〔既定〕／向聴を保ってランダム／完全ランダム）。
   ツモ牌が最善の牌（1・2 の評価で最も切ってよい牌）ならどの方式でもツモ切りし、方式は手出しの牌選びにだけ使う
4. 目標枚数の UI は D 案（「選択中」の一覧に `−`／`+`、項目のボタンには `×N` バッジ）
5. 判定の探索の下限は「足りない枚数の最大値」ではなく「合う牌が重ならない項目の組の、足りない枚数の合計」を使う
   （重ならない項目が多い条件でも探索が打ち切りにならないように）。探索は 20 万ノードで打ち切り、その場合は「判定できません」扱い
